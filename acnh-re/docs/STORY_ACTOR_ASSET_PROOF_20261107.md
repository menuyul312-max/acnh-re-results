# Story, actor, and asset proof crosswalk — ACNH 1.0.0

This report joins the opening and main progression story graphs to actor, stage, UI, animation, text, and audio source records. It covers arrival through Island Designer and the staff roll boundary. The detailed claim ledger is [story_actor_asset_proof_20261107.json](../output/gameplay/story_actor_asset_proof_20261107.json).

`EF` means an action, query, call, message reference, or stage request decoded from a BFEVFL node. `STAGE` means a source BYML actor or transition projection. `PARAM` means a decoded BCSV/param record. `ASSET_SOURCE` means a parsed raw member exists in the supplied additional archive. `CAT` means an external catalogue row. Catalogue paths are not payload checks. None of these labels means a full runtime playthrough was executed.

## Actor asset joins

The best static actor join is a three-step source chain: a stage or flow names the NPC code, `B_data/Bcsv/SpNpcParam.bcsv` maps that label to `ResName`, and the external model catalogue contains a row with the same `Asset_ID`. For example, the dream stage's `tkkA` code joins to `NpcSpTkk`, whose catalogue row is labelled K.K. Slider. Tom Nook's `rco` code similarly joins to `NpcSpRco`. This supports the configured resource name; the catalogue row and its generated GLB path do not verify a payload or runtime model load.

The source tables also give a useful story audio join. Campfire EventFlow passes `MusicName=4318`; `SoundAudioMusic.bcsv` row 103 maps `RefItemUniqueID=4318` to audio-music id 95, `Minnaatsumare`, and `ItemParam.bcsv` identifies item 4318 as `FtrMjkMainTheme`, a K.K. first-live music item. This is stronger than a name-only candidate, while still leaving the waveform and exact `Sound/Resource` file unverified.

## Animation, text, and UI boundaries

The supplied additional archive has 83 parsed `AnimationSequence` files (1,159 nodes and 10,001 transitions in the parser output), including `EventObjCampfire.root.asb`. Scene EventFlow nodes issue commands such as `NpcCheers`, `NpcRequestAction`, and `NpcSpDrRhythm`; the cited nodes do not identify an exact ASB clip. The `AnimationInfo/NpcSpTkk.byml` and `AnimationInfo/NpcSpRco.byml` files are present in that archive, but the character model/animation payload is not.

Story flows contain exact UI action classes, form types, and application names. The added archive also has 523 parsed BFLYT layouts, including village-name keyboard, character creation, MenuDevice, and StaffCredit layouts. No direct key from the cited EventFlow actions to those exact BFLYT members was recovered. These are scene-relevant candidates, not confirmed loaded screens.

EventFlow message actions identify archive/label keys. A follow-up directly checked 460 refs across 17 cited EventFlow files (16 with message refs), 425 unique keys, and 14 locale directories: all 6,440 selected EventFlow×locale pairs matched an exact MSBT member/index/label and all 6,440 BDLI label/index checks passed. The earlier `message_archive_not_supplied` value is inherited from the initial corpus index and is a false negative for this subset. Supplemental archive build/version remains unproven; dialogue text is not included. See [STORY_MESSAGE_CUE_FOLLOWUP_20261107.md](STORY_MESSAGE_CUE_FOLLOWUP_20261107.md) for the full ledger and limits.

## Conversion and evidence limits

The BFEVFL inputs were decoded into EventFlow trees with indexed actions and message keys. Stage BYML projections retain source path, source hash, actor source pointers, actor kinds, and argument strings. BCSV tables were decoded to named rows to join NPC labels, resource names, music item IDs, and BGM control states. The additional RomFS archive was separately audited and its SARC/SZS-contained UI, MSBT, ASB, and new BYML records were parsed to structured JSON. External model/audio catalogue CSVs were converted to catalogue JSON and treated as references.

The 1,171 original B_data paths in the additional archive match the baseline by hash, supporting the ACNH 1.0.0 EventFlow/Stage/BCSV source claims. The added paths do not have independent per-file build metadata. The audit reports no `Model/` or `Sound/Resource/` source directories, and the generated GLB/OGG paths in catalogues are references only. No game runtime, Godot project, or build was used.

The JSON ledger records each path, entry, event index, source pointer, key, and available parameter join. Remaining limits include model/audio payloads, runtime animation/UI dispatch, exact supplemental message archive version, stage dispatch, and credits trigger. The separate message/cue ledger records the verified MSBT/BDLI joins without dialogue bodies.
