## Findings

The upstream score and readiness chain remains as recorded in the island-rating follow-up: the lowest authored K.K.-eligible result is eight constructed NPC houses, Nature score at least 270, Life score at least 160, and Isabelle result 2 (the explicit 3-star message). The aggregate and save-copy callsites are statically identified, but their runtime order, save commitment, and the full evaluation-to-reservation sequence have not been executed together. The native `0xfd8920` gate requires at least one elapsed day, `IslandEvaluationClearTkkLive` ON, and `TkkFirstLive` OFF before it enables the first-live announcement path.

The public-announcement EventFlow makes the `cMainFieldFirstLive` request only from `Demo_PublicAnnouncement:PAnnounceSza` event-array index 41 when `TkkFirstLiveReserved` is ON. Native registration maps `EventFlowActionSystemRequestChangeStage` to the `TargetStage` string parameter, and handler function `0x304f80` recognizes table index 26 for `cMainFieldFirstLive`; its branch at PC `0x305adc` calls `0x306910` (raw bytes `8d030094`). A new raw-callsite check shows that `0x306910` prepares a request and calls generic helper `0xfefee0` at PC `0x306afc`. That helper calls request validator `0xffc200` at `0xfeff30`; if accepted and its global request manager exists, it calls `0x11ef360` at `0xfeffc0`. The latter reaches `0x11f0990` at `0x11ef380`, which copies the six-field request record into manager offsets `+0x258..+0x26c` and, for the selected mode, `+0x240..+0x254`.

This closes the EventFlow action to a generic native request-record handoff. For this call the mode argument is zero, so the record copier writes the six request fields at manager offsets `+0x258..+0x26c`; its separate mode-1 path also copies to `+0x240..+0x254`, but that path is not exercised here. The request manager's consumer to the generic `Stage/Game` loader remains open: the loader path is separately visible at `0xfe6f10` → `0xfef090` (call PC `0xfe7140`), but no direct call or resolved pointer dispatch joins that path to the `0x11ef360` request record. `MainFieldDemoFirstLive.byml` remains the best filename match and includes `commonOutdoor`; `commonOutdoor` actor row `/3cbaa541/2` is registered type index 5, `NpcActorMgr`. The actor-manager factory and its method are identified, and method `0xc685a0` calls builder `0xc70da0` at `0xc686ac`. The builder contains `E_FirstLive_NPC_0` and `AI_NPC_Tkk_FirstLive`. The exact stage-label-to-BYML mapping and actor-row indirect factory invocation remain open.

The K.K. actor AI-to-talk boundary is stronger than the earlier caller index suggested. `AI_NPC_Tkk_FirstLive:Root` event-array index 5 passes `FlowName=SNPC_tkk_Live` and `EntryName=Tkk_LandFirstLive` to `AI_NPC_Common:ContinueSpeak`; that entry forwards both arguments to `EventFlowActionSetNpcSpeakFlow`. The native action registry recognizes the action and its two string parameters. This proves the authored source graph selection, conditional on the AI root running; the stage/actor activation described above remains unjoined. `SNPC_tkk_Live:Tkk_LandFirstLive` then contains the live demo, the first-live completion flags/counter, and the authored return request to `cMainFieldPlayerHouse` at event-array index 94. The day-change native dispatcher `0xf545f0` later reads `TotakekeLiveCount`, sets `TkkFirstLive` when the count is at least one, and clears `TkkFirstLiveEnable`.

Two separate authored app-install paths appear after this boundary:

1. **Island Creator phone call.** `Demo_PublicAnnouncement_Process:Root` can take its `TargetMode=0` branch at event-array index 202 to `Process_Only_PAnnounce` (index 203). That entry reaches `ChkStartGamePhoneCall` at index 209; `ChkStartGamePhoneCall` begins at index 158 and calls `CheckPhoneCallIslandCreater`, whose entry begins at index 159. The latter checks `TkkFirstLive` ON, `MainmenuConstructLicense` OFF, and an `EventBranch AddDay=0` result other than case 3. Its branches set `StandByPhoneCallIslandCreater` and `StandByGameStartPhoneCall`. `Player_StartGamePhoneCall:Root` calls `ChkPhoneCall`; when the Island Creator pending-call flag is selected, its flow dispatches to `IslandCreaterTell` or `IslandCreaterTell_Continued`. The `IslandCreaterTell` route contains event-array indices 145 and 146 (events `Event151` and `Event152`): set `cPlayer:MainmenuConstructLicense` ON, then `UIMenuDeviceAppear(EventType=cInstall, Application=cConstructLicense)`. The native action registry confirms `UIMenuDeviceAppear` is a registered action with string `EventType` and `Application` parameters. The exact engine call that consumes `StandByGameStartPhoneCall` and starts this EventFlow is not joined here, and the action-to-menu-page load remains unproven.

2. **Nook invite talk.** `AI_NPC_Rco_FirstLiveInvite:Root` passes `SNPC_rco_55_TkkFirstLive:InvitePlayerHouse` through `AI_NPC_Common:VisitSpeak`. In that entry, event `#31` clears `StandByRcoVisitMyHomeAfterTkkFirstLive`; the `SystemHasBaggageSpace(CheckNum=1)` branch and `TkkFirstLiveReserved` gate control the reward routes. On query case 0 with reservation ON, the flow grants item 4318 and reaches `MainmenuConstructLicense` ON followed by `UIMenuDeviceAppear(cInstall,cConstructLicense)` (`#16`/`#17`). The alternate query case 1 selects item 4318 and sends it by mail; that branch has no app-flag write or app-install action in this entry. The source data therefore contains a concrete app-install branch but does not establish its runtime selection or connect the first-live standby writer to this AI resource.

The credits edge remains open. `State::cPlay` callback code at `0x146f2c0` calls generic helper `0x1470e90` at PC `0x146f34c`; the helper selects the `StaffCredit` resource case. A code-pointer sequence has `0x146f2c0` at slot `0x330db20`, but its owner and dispatch meaning are unresolved, and the direct-call index has no incoming caller for `0x146f2c0`. No edge from the first-live return request, K.K. completion flow, or Island Creator phone flow to that callback is identified. The bounded EventFlow search in the earlier report found no `StaffCredit` or `StaffList` token among the 456 indexed EventFlows.

## Evidence bounds

- The EventFlow graphs establish authored actions, branches, arguments, and flags. They do not show that a save followed those branches.
- The native call scan establishes direct AArch64 `BL` edges; the stage loader continuation, actor-row factory selection, request-manager dispatch, and callback ownership can be indirect and remain unresolved where stated.
- `code_pointer_arrays.json` is a relocated pointer sequence inventory, not an ownership or dispatch proof. In particular, slots containing `0xc685a0` and `0x146f2c0` do not close their upstream story events.
- `MainFieldDemoFirstLive.byml` and `commonOutdoor.byml` are decoded resources that match the candidate chain, not proof that the runtime selected them for `cMainFieldFirstLive`.
- The app action registry proves a native action class and parameter names, not the loaded MenuDevice page or a runtime installation.
- No game, save, or integration fixture was run for this report. No Godot files were changed.
