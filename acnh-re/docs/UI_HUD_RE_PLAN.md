# Rencana sisa reverse engineering UI/HUD

Status diperbarui 6 November 2026. Fokus hanya UI/HUD ACNH 1.0.0. Analisis RomFS/ExeFS yang tersedia tetap lokal; Godot hanya dibaca dan tidak ada push.

## Temuan yang sudah ditutup secara statis

- Rekonsiliasi seluruh archive/member BFLYT dan indeks layar, pane, group, part reference, material, tekstur, font, serta animasi.
- Decode seluruh section CNT1/USD1/PRT1/WND1 yang ditemukan; 356 CNT1, 2.164 USD1, 1.715 PRT1, dan 550 WND1 tanpa error parser.
- Pemetaan 803 `ui2dsys` records: 453 `AnimTagName` dan 350 `ProceduralShape`; field shape disimpan, tetapi efek renderer belum dikonfirmasi.
- Pemetaan 160 BND1/SCR1 common pane records serta 457 blok group yang dibatasi marker. Semua 1.552 group di dalam blok hanya mencakup section `grp1`; 523 `RootGroup` berada di luar blok.
- Enumerasi semua 52 jenis-section/ID properti animasi yang teramati; 0 properti unresolved. Memisahkan 15 FLEU dari 16.147 kurva dan mengikat semua target User ke key USD1 unik pada pane terkait.
- Memperbarui hitungan animasi lama. FLEU sebelumnya keliru dihitung sebagai track/curve key; angka kanonik sekarang 16.147 kurva + 15 record FLEU.
- Menambahkan konteks BFLAN pembawa untuk seluruh FLEU: tujuh animasi dengan frame count/loop dan jumlah kurva biasa. Kesebelas record `C_Id` berada pada animasi 2-frame; `Cursor3_Wait` loop 720 frame dengan `base_count` 50. Ini membuktikan `base_count` bukan durasi, tetapi tidak mengungkap makna array atau waktu penerapan native.
- Memetakan enum state kontrol `0..17`, 29 trigger transisi key/touch/inverse/validity pada `0x1dd0c20`, konfigurasi `*Cursor`/`Draggable`, dan binding tag `UB_Select`, `UB_Unselect`, `UB_Decide`, `UB_DispValid`. Ini bukti state machine kontrol statis, bukan bukti routing input platform.
- Menemukan callsite dispatch untuk semua 13 ID aksi dari `FocusKey` sampai `Inactive`. Emitter bertipe mengidentifikasi `DecideKey`, `Invalid`, `Check`/`Uncheck`, `RepeatKey`/`RepeatTouch`, dan `Active`/`Inactive`; Focus/UnFocus dan DecideTouch kini punya callsite statis, tetapi sumber event perangkat, penerima konkret, dan timing belum terhubung; provider callback kontrol diketahui dibuat lewat descriptor `+56`/slot `+24`, disimpan pada `+1256`, lalu dipanggil melalui slot `+32`, tetapi implementasi provider belum ditemukan.
- Menambah katalog state machine native yang teramati: kontrol bersama 18-state/29 trigger; Ring Tool 3-state (`SelectActiveReg`/`UnSelectActiveReg`/`DecideActiveReg`); profil Decide/inverse 8-state; ScrollBar dengan 5 ID aktif dan getter 6 nama; Selector 4-state; drag/drop bertag `*CaptureTarget`; serta korelasi getter enum berdasarkan rentang state, dengan pemasangan enum ke objek masih belum terbukti.
- Memetakan input sentuh native: aplikasi menginisialisasi Npad/touchscreen dan `guiTouchManager`; wrapper update `0x14b8e50` memanggil poller `0x14b8f60`, hit-test `0x14b94c0`, lalu traversal dua pohon kontrol melalui `0x14b7a10`. Hit-test menyimpan target kontrol pada pointer record; traversal mencocokkan target dan menjalankan helper pointer-state dengan callback virtual. ID `TouchSelect`/`TouchUnselect` masuk ke buffer histori pesan. Slot factory callback kontrol (`+24`) dan invocation (`+32`) kini terpetakan untuk method yang juga memuat `FocusTouch`/`DecideTouch`; implementasi provider serta edge dari `guiTouchManager` ke method itu, state machine spesifik, atau CNT1 masih belum terbukti.
- Menemukan jalur sampling Npad terpisah: `0x1968840` menginisialisasi Npad, mendaftarkan ID 0–7 dan handheld 32, serta style mask `0x1f`. Vtable manager menempatkan update `0x1968b80` pada slot `+0x20`; fungsi tersebut memilih lima varian `GetNpadStates` dan membaca sensor/getaran. Belum ditemukan edge dari hasil polling itu ke 13 ID aksi UI. Jalur kedua memakai `VibrationPlayer`/`VibrationWriter` dan graf `VibrationTarget`/`VibrationMixer`/`VibrationNodeConnection`; pemuat pola serta 11 callsite `Write` dipetakan, tetapi asset dan event pemicunya belum diketahui.
- Mengikat factory `MainScreenPage` (`0x1229c50`, alokasi `0x648`) ke konstruktor `0x1226540` dan pointer sequence address point `0x310f0e0` lewat relokasi ELF `0x33076d8 → 0x310f0d0`; sequence berisi 79 slot. Slot 25 membuat 27 child/context entries pada offset objek `0x570..0x640`. `SmartPhoneIconPage` (`0x144f7a0`, alokasi `0x570`) terikat ke address point `0x3131c18` dengan 79 slot. Slot 46 pada keduanya mengembalikan identifier `MainScreen` (`0x1228a90`) dan `MainScreenSmartPhone` (`0x144f010`) yang persis cocok dengan nama BFLYT. Kesesuaian identifier belum membuktikan loader memanggil getter atau page merender layout itu.
- Memperluas pola itu menjadi katalog 135 factory page dan mengaudit slot 46 di setiap pointer sequence: semua 135 slot direlokasi ke getter ADRP/ADD/RET unik yang mengembalikan string; seluruh identifier unik, 134 cocok tepat dengan nama layout katalog, satu `SwkbdDummy` tidak cocok. Setiap getter hanya menjadi target relokasi pada slotnya, dan tidak ditemukan instruksi langsung B/BL ke getter. Pemetaan disimpan di `output/ui_hud/page_layout_method_bindings.json` dan dibuat ulang oleh `tools/ui_hud_page_layout_bindings.py`. Ini crosswalk identifier statis, belum bukti receiver indirect, handoff ke loader, atau render.
- Membuktikan jalur registrasi factory: seluruh 135 factory memanggil `0x1da8220`, yang mengubah state objek `+0x48`, dispatch slot 5 ke `0x1da5380`, memasukkan node ke intrusive list melalui `0x1967c40`, dan menaikkan counter. Helper seleksi `0x1da8270` punya satu caller yang ditemukan; ia menguji page melalui slot 17 → thunk bersama → slot 30 bersama, bukan getter layout slot 46. Arti koleksi, selector, callback, dan lifecycle masih belum terbukti.
- Membandingkan nama kelas factory dengan nama layout menghasilkan 74 kandidat setelah akhiran `Page` dilepas. Kandidat berbasis nama tetap dibedakan dari bukti slot 46: getter mengembalikan identifier layout untuk 134 page, tetapi pemanggilan loader dan kepemilikan runtime masih belum terbukti.
- Membandingkan 31 nama pada flag registry dengan kelas factory menemukan 23 kecocokan setelah prefiks `c` dilepas; delapan tidak cocok secara tepat. Karena pseudocode registry tidak menyimpan pointer factory, seluruh pasangan tetap kandidat nama.
- Memeriksa seluruh native string-reference index: literal `MainScreenSmartPhone` tidak terindeks sebagai referensi string, tetapi slot 46 `SmartPhoneIconPage` membentuk pointer ke string tersebut melalui ADRP/ADD. Nilai identifier statis terbukti; penggunaannya oleh loader tetap perlu ditelusuri.
- Memetakan tipe kontrol native `ButtonNormal`, `ButtonCheck`, `ButtonRepeat`, `ButtonFocusActive`, dan `ButtonSelBox` ke mode ID `1..5`, serta resolusi `Inherit` melalui rekaman induk.
- Mengorelasikan state machine tersebut dengan CNT1: 91 `LpUniteButton` memiliki 18 nama animasi yang selaras dengan state/trigger native; profil `ButtonNormal` (12), `ButtonCheck` (3), dan `ButtonRepeat` (4) cocok dengan action table dan emitter bertipe.
- Memetakan dua tahap dispatch tipe komponen UI: `0x1db2140` memilih slot setup per tipe dan `0x1672890` slot follow-up. Dua urutan pointer dalam `code_pointer_arrays.json` sejajar dengan slot tersebut dan memberi kandidat alamat target. Pemindaian text/relokasi `main` tidak menemukan referensi inbound statis ke address point-nya, sehingga kaitan vptr tetap belum terbukti. Audit setup mengorelasikan 12 slot tipe dengan badan handler. Sepuluh jalur memiliki call edge ke factory beserta token kelas pada `string_refs` (PartsCtrl, UniteBtnCtrl, DragBtnCtrl, KeyDecideIconCtrl, CharAnimCtrl, TextAnimCtrl, TraceGaugeCtrl, NumberAnimCtrl, MultiNumberAnimCtrl, TimerCtrl); `LpSelector` dan `LpScrollBar` ditautkan ke helper/tag state tanpa token factory yang ditemukan. Disassembly AArch64 mentah menunjukkan 11 target follow-up kandidat berisi `ret` saja; lima lainnya berisi pola serupa yang memanggil virtual pada objek dan menyimpan pointer konteks. Jalur `ui2dsys` mengidentifikasi factory `BoundingCtrl`, `ScrollBtnListCtrl`, dan `ScrollSignCtrl`. Binding record per instance dan arti field/efek target masih terbuka.
- Menghasilkan preview HUD sebagai alat inspeksi, bukan hasil render final.

## Urutan pekerjaan yang tersisa

1. **Tutup pemilihan part bila bukti tersedia.** Call path native kini menegaskan pembentukan key resource child dan permintaan member `.bflyt`, tetapi tidak memperlihatkan archive precedence. Langkah berikutnya memerlukan pencarian allocator/resource index lebih dalam atau trace runtime; simpan dua kandidat hingga hasil itu diperoleh.
2. **Lanjutkan controller dan dispatch UI.** Semua 13 ID aksi memiliki callsite statis; jalur sentuh kini menghubungkan polling hingga callback virtual kontrol, tetapi vtable penerima belum terpetakan ke aksi/FSM/CNT1. Polling Npad dan worker `VibrationThread` sudah dipetakan sampai `SendVibrationValue`; constructor juga menyiapkan ring inline berkapasitas 16 record. Producer ring, reset indeks baca, pemicu gameplay, dan hubungan kedua jalur haptik dengan aksi UI masih belum terbukti. Registry 135 factory page sudah dikatalogkan dan getter slot 46 memberi crosswalk 134 identifier layout; slot lifecycle lain serta handoff getter ke loader belum terbukti. Berikutnya telusuri scheduler ke slot page, pemuatan layout, modal push/pop, open/close/back, restore focus, dan teardown.
3. **Tutup konsumen khusus.** Native membaca userData untuk border, color overlay, gradation, drop/inner shadow, gradation mask, effect link, text adjustment, serta capture statis/dinamis. Berikutnya hubungkan pembaruan FLEU ke field itu, petakan `C_Id`, CNT1 callbacks dan flag PRT1, lalu uji BND1/SCR1/ProceduralShape terhadap renderer.
4. **Uji renderer dengan referensi sinkron.** Bandingkan source capture dan hasil render untuk viewport, origin, material, BNTX channel/swizzle, sampler/blend, font locale/fallback, WND1, clipping, shader pass, dan keyframe. Catat layar, state, frame, resolusi, dan perbedaan. Dump aset saja tidak cukup untuk memastikan pixel parity.
5. **Bangun konverter Godot setelah bukti cukup.** Pertahankan pane tree, sublayout instance, overrides, group ranges, material, font, track, dan data FLEU. Buat fixture per jenis pane dan satu layar lengkap; jangan menandai visual parity sebelum cocok pada capture game.

## Kondisi selesai dan blocker

Pemetaan statis format berhenti pada titik bahwa seluruh section yang teramati memiliki parsing terstruktur atau tersimpan sebagai raw/hash, semua properti animasi teramati diberi label, dan referensi resource ambigu ditulis bersama kandidat. Jalur sentuh terlacak sampai callback virtual, Npad sampai sampling HID dan pengiriman vibration, dan page factory sampai vtable dan getter slot 46 ke 134 identifier layout; handoff ke loader, implementasi callback sentuh akhir, producer ring vibration, sumber payload/jadwal graf VibrationPlayer, routing aksi Npad, lifecycle show/hide/modal, pembaruan FLEU, pemilihan part archive, pemanggilan getter oleh loader, serta instansiasi/render page-to-layout belum tertutup. Perbandingan render memerlukan capture game yang sinkron; bila tidak tersedia, parity harus tetap dilabeli belum terbukti. Bukti tambahan dan rantai fungsi native tercatat di `acnh-re/output/ui_hud/native_ui_traces.json`.

Belum ada blocker yang mengharuskan perubahan Godot atau push. Blocker aktual untuk klaim perilaku adalah tidak adanya trace/runtime yang membuktikan urutan loader dan state UI dari aset statis saja.
