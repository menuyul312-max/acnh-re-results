# Villager plot-to-first-live continuity follow-up (ACNH 1.0.0)

Static continuity trace from the three migrant plots through first move-in, the first campsite visitor, and the first K.K. live. This follows the remaining actor, AI, talk, and save-progress joins after [the building-placement proof](BUILDING_PLACEMENT_PROOF_20261107.md). It does not repeat plot placement or furniture requirements. No game execution, save mutation, model/audio claim, or Godot change was made. Machine-readable evidence and provenance are in [the accompanying JSON](../output/gameplay/villager_plot_firstlive_continuity_followup_20261107.json).

## Result

The static sources close the applicant-selection and save-record portion of the A/B/C plot flow. `System_MigrantsQuestProcess` and the public-announcement process pass `SettlerType` 0/1/2 to completion and selection actions. Their native handlers record completion order, choose an NPC ID from a `NpcLooks` filter, and store that ID in the corresponding A/B/C save entry. The next-day move-in processor consumes that same entry and writes a villager record and move-in flags. A native stage-builder body then shows how completed resident slots can become actor records with an indoor/outdoor AI path.

The important break is between those save writes and a demonstrated runtime actor/talk selection. The actor-builder body has no resolved stage-manager caller, the generic field stage row carries no plot or resident ID, and the indexed flow graph does not name an initial conversation entry for A/B/C residents. Thus the reports establish a static candidate path, not an end-to-end visible move-in.

The first campsite visitor has a more complete talk subgraph. Once the camp is ready, EventFlow requests the first visitor; the day-change selector can force a visitor, and a camp actor-builder body constructs an `AI_NPC_Camp` path. That AI flow selects `NNPC_Spot_Camp:Root` and `cSpeak` for the pending first-visitor case. Its normal first-camper flow contains the greeting and choice messages, then reaches `Set6thVillager` and the completion flags. The native action writes the chosen camper ID into NPC slot 5. The stage-to-builder activation and the later slot-5 housing-to-visible-actor join remain open.

The K.K. endpoint is the one already bounded in the [first-live dispatch follow-up](CORE_STORY_FIRSTLIVE_STAGE_DISPATCH_FOLLOWUP_20261107.md). The stage request and native first-live actor/AI builder are established as a candidate path, and the AI root only calls `AI_NPC_Common:ContinueSpeak`. The dedicated `SNPC_tkk_Live:Tkk_LandFirstLive` entry has no indexed caller. The actor-to-talk-entry bridge therefore remains open. If that entry runs, its EventFlow subflow writes the first-live progress flags and increments the live count; the day-change routine later marks `TkkFirstLive` when the count is positive.

## Native PC anchors and limits

The two plot action-handler vtables are resolved from `event_handlers_resolved.json`: `CompleteSettlerQuestSubject` factory `0x452830`, constructor `0x33bea0`, execute slot `0x33bf50`; `DecideSettlerNpc` factory `0x44ecb0`, constructor `0x33c5b0`, execute slot `0x33c660`. In `0x33bf50`, the `SettlerType` parameter is loaded at `0x33bf64`; settler-member lookup and the `0xfc2f00` call occupy `0x33bfa4–0x33bfbc`; the selected completion key is prepared at `0x33c04c`, and `0xf44e70(...,1)` writes it at `0x33c058`. In `0x33c660`, the parameter load is at `0x33c674`; plot indexing/empty-entry check spans `0x33c6fc–0x33c710`; the picker call is `0x33c728`; selected-ID store/validation is at `0x33c744–0x33c75c`; plot flag query is `0x33c784` and the event notification call is `0x33c798`.

In `0xf8c540`, the next plot type, completion/housing-progress check, and plot flags are read at `0xf8c5b8`, `0xf8c5f4`, and `0xf8c65c`; fallback filtering/picking starts at `0xf8c6fc` and calls `0xf8d860` at `0xf8c73c`. The NPC ID write is `0xf03360` at `0xf8c780`, `FromSettlerQuest` is written through `0xf497c0` at `0xf8c7bc`, and move-in helpers run at `0xf8c7d4` and `0xf8c7e8`.

For campsite actor/talk continuation, the builder calls `0xf7d760` at `0xc6ce98` and submits its constructed actor at `0xc6d128`. The native action `Set6thVillager` is registered with factory `0x44f8b0`, constructor `0x313f40`, and execute slot `0x313ff0`; its Step 0 branch reaches `0xf86f30` at `0x3140b8`. The helper writes slot 5 through `0xf03360` at `0xf86f60` and notifies NPC index 5 at `0xf86fc0`.

All raw instruction addresses and pseudocode summaries are from the ACNH 1.0.0 `main` NSO identified in the JSON. **PSEUDO** means statically recovered control/data flow; no function here was executed. **EF** proves source graph content and action parameters, not that the engine entered that event. **STRUCT/TBL** proves parsed stage/table records, not runtime use. The first-live stage and actor details are cross-references to the prior dispatch follow-up so this report does not duplicate its loader/placement investigation. `AI_NPC_Normal`/`AI_NPC_Outdoor` and first-live/camp resource names do not establish a rendered model, audio playback, or a first-talk selection.
