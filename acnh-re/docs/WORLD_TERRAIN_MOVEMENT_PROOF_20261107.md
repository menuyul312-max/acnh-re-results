# ACNH 1.0.0 movement, terrain, and story traversal evidence

This report joins the existing player-motion, collision, ground-query, terrain, island-loader, water/terraform, and core-story artifacts. It records only what the ACNH 1.0.0 sources support. No Godot or build work is included.

## Finding

The repo proves several bounded native movement and terrain helpers, and the EventFlow story orders player-selected construction steps. It does **not** yet prove a live player-control-to-collision-to-traversal path or connect that path to a successful bridge, ladder, plot, or Island Designer edit. The core story establishes progression around placement flags and building counts; it does not establish that the player physically crosses a bridge or climbs to a plot before the next quest step.

Evidence labels in this report follow the repo convention: **EF** is EventFlow structure/order, **TBL** is table data, **STRUCT** is parsed data layout, **PSEUDO** is static native code reading, **NATIVE** is a bounded execution of original native instructions on a prepared fixture, **CAT** is a catalog candidate, and **OPEN** is an unproven link. A native fixture is not a running game trace.

## Player movement and collision boundary

1. **Stored movement components to actor position — NATIVE, bounded.** `0xdac550` was executed for 3,205 finite fixture cases on its non-animation branch. With player memory supplied, it reads `player+0xf58` and `player+0xf50` as local movement components, rotates/scales them using yaw and `context+0xd30`, adds the resulting XYZ delta to `actor+0x278`, and writes history/delta fields. The original helper callees ran without stubs. This does not identify the controller/HID producer for those fields; they should not be described as raw stick input. See [player_position_native.json](../output/mechanics/player_position_native.json) and its [native tool](../tools/player_position_native.py).
2. **Vertical velocity fragment — NATIVE, bounded.** `0xe17cb0` fragments read supplied time records and a supplied target, run the original gravity lookup and ballistic solver, store velocity at `player+0x574` and a motion triplet at `player+0xf58`, then add X/Z velocity to the actor through a separate native instruction range. Eight composed cases pass, but a gap is reconstructed between ranges. The time/target producers, duration units, update cadence, and whole frame function are not established. See [player_xz_position_native.json](../output/mechanics/player_physics_remainder_20261107/player_xz_position_native.json) and [ballistic_velocity_native.json](../output/mechanics/ballistic_velocity_native.json).
3. **Vertical correction — NATIVE fixture plus PSEUDO edges.** Eleven fixtures enter a selected branch of `0xda86b0` with state W0 supplied by the harness; selected branches write actor Y or stop before querying `0x7bccf0`. Twelve `0xdac780` cases separately test early return, branch edges, and a Y sink fed an externally supplied scalar. These do not establish how the live state/query result is produced or prove landing. See [collision remainder](COLLISION_REMAINDER_20261107.md) and [post-motion remainder](PLAYER_POSTMOTION_REMAINDER_20261107.md).
4. **Collider candidate query — OPEN.** The caller register shape to `0x7bccf0` is statically mapped: actor position pointer in X0, optional output null in X1, W2=0, and S0=0. The attempt faults at `0x172780` because a fresh sandbox's world-root slot contains null; subsequent reads treat mapped ELF bytes as a grid pointer. The fixture produced no candidate, ground scalar, or gameplay query result. This is an emulator-context fault, **not** an ACNH gameplay fault. See [player_7bccf0_boundary_native.json](../output/mechanics/player_collider_query_remainder_20261107/player_7bccf0_boundary_native.json).
5. **Collision response — partial.** `collision_response_native.json` verifies full-mask storage helpers and selected policy/scalar fragments over 62,702 cases. `collision_native_verification.json` verifies four enum compare/select blocks. Neither executes a complete collision solver, collider selection, geometric penetration response, friction, or navigation. The parsed state table includes a `Move` row with background mode `Normal`, but names and table configuration alone do not prove live physical behavior.

## Ground, terrain, navigation, and edit helpers

- **Ground sampling — NATIVE on reconstructed grids.** `terrain_native.json` verifies index/world conversion, base/overlay record reads, and three four-point ground aggregators. The tested grid is row-major (`x + width*z`), runtime records are 52 bytes with four sector attributes at offsets 48–51, and overlay attributes independently replace base values unless the overlay byte is sentinel 7. Index-to-world XZ uses 5.0-unit cells and a 2.5-unit center offset; the four-point chain samples the center and quarter-cell offsets. `WaterCheck` is true only when all four sampled attributes are set in the tested aggregator; `PlayerNoEntry` is true when any is set. This is not a complete walking/burying/water rule set. Dynamic object-ground overrides are absent from the fixture.
- **Terrain-to-navigation — NATIVE, but NPC pathfinding.** `terrain_nav_flags_native.json` verifies height/flag decoding, directional node callbacks, costs, and eight height→word→node→A* chains over reconstructed grids. The tests show how selected height differences and flags affect NPC navigation masks/path costs. They do not show the player movement solver consuming these masks, nor complete cliff, gap, surface-type, and live terrain behavior.
- **Rectangle checks and mutations — NATIVE, fixture-scoped.** `terrain_region_check_native.json` covers a rectangle predicate on reconstructed records, including a tested height-difference threshold near 0.11; it does not test all 12 terrain height samples or geometric collision. `terrain_region_mutation_native.json` verifies inclusive region word-bit mutation. `native_region_release_trace.json` executes `0x168140 → 0x165240 → 0x181ae0` on a constructed registry/list/world fixture and clears bit `0x40` in a 3×3 region. It does not link that cleanup to live MakeFall/BreakFall actions, commit/save, or player steering.
- **Island preset transfer — STRUCT/PSEUDO, not a full loader execution.** Ninety-six LandMaking BYML presets contain 112×96 row-major cells of 14 bytes each: two unit/variation/rotation layers and a height byte. Static code maps `0x529910 → 0x528bf0 → 0x558f40`; the last function copies those fields to destination cell accessors when template and destination pointers are present. Variation indices are clamped to the destination unit's table limit; the source height byte is copied. The generator/setup/resource loader were not run with live game objects. The destination accessors' allocation stride and the mapping to the separate 52-byte ground/PBC records are unresolved.
- **Water/terraform — TBL plus isolated native cleanup.** `FieldLandMakingActionParam` has 17 rows; rows 9 and 10 describe `MakeFall` and `BreakFall`, each with range 3×3 and layer `No0`. These are table values only: no player action/validator/save caller consuming them is identified. The release fixture's flag clear is a separate cleanup path and cannot be presented as successful water/terraform behavior.

## Remaining blockers

- HID/controller sample → player movement component producer → frame scheduler → position update is **OPEN**. The tested position helper receives reconstructed player fields.
- Full `0xe17cb0` scheduling, target/time producers, gravity timing, jump/vault/ladder linkage, and units are **OPEN**.
- Initialized world-root, broad-phase grid/list, candidate selection, floor/landing scalar, collision geometry, moving-body/friction response, and post-query Y correction are **OPEN**. The query fault above is only a sandbox setup failure.
- Player traversal rules for water, river, cliffs, bridge endpoints, ladders, slopes, and terrain collision are **OPEN**. NPC A* evidence must not be substituted for player traversal.
- Player preview → placement validation → world object/preset mutation → refresh → save/rollback for bridge, plots, and Island Designer edits is **OPEN**. Current EventFlow proves progression requests and flags only.
- Preset-to-PBC/collision conversion is **OPEN** because the relevant source payload and runtime bootstrap are missing; a 14-byte/52-byte size/schema relationship is not itself a conversion.

Overall status: **OPEN** for the requested end-to-end movement/terrain/traversal path. Existing **EF**, **TBL**, **STRUCT**, **PSEUDO**, **NATIVE**, and **CAT** evidence narrows the component contracts and story order, but none closes the live integration.
