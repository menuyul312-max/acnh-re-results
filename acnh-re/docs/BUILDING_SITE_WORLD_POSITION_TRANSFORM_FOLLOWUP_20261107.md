# Building-site coordinate conversion and actor handoff follow-up

**Date:** 2026-11-07
**Scope:** ACNH 1.0.0 static trace from the `BuildStructure` site record through coordinate parsing, special coordinate-dependent branches, and the component vtable handoff. This adds raw-instruction evidence to [the BuildingSiteIndex follow-up](BUILDING_SITE_INDEX_BLACKBOARD_NATIVE_FOLLOWUP_20261107.md). No save, game, Godot scene, model/audio payload, or build was executed or changed.

## Result

The selected list pair is converted by native code into a 3-float vector with lanes 0 and 2 set to `10*n + 5`; lane 1 is left untouched. The exact code is at ELF VA `0x568360`, reached by the selected-record parser at PC `0x4e1758`, which itself is reached from `BuildStructure` at PC `0x36a37c`. In the later coordinate-dependent helpers, the vector's lanes 0 and 2 are read as X and Z and quantized to 5-unit grid indices using floor division, including for negative values. This establishes an integer-pair-to-world-coordinate convention at the parser boundary and an X/Z grid convention in downstream field queries.

The trace then reaches a dynamic actor-component method: `0x2eae0` loads the object vtable and calls its slot `+0x128` with the converted vector. The actual slot implementation remains unresolved because the component vtable pointer is runtime-provided through the actor's `+0x68` field. I found no statically resolved final transform write, rotation/footprint calculation, named overlap/terrain validator, preview-to-build model binding, collider/PBC consumer, or durable save-instance write on this chain. The two special coordinate helpers inspect/query field-grid state, but their return predicates are not demonstrated to be the placement validator.

## What the current chain proves about placement coordinates

- The native pair-to-vector transform has a ten-unit pitch and five-unit half-cell offset: `(pair0*10+5, unchanged Y, pair1*10+5)`. This is the exact arithmetic in the parser's conversion helper.
- The later field-query path consumes vector lane 0 and lane 2 as horizontal coordinates and indexes the grid at five-unit resolution. This grounds the axes as X/Z for those queries.
- There is no translation, island-origin lookup, axis swap, sign inversion, rotation, height sample, or footprint expansion inside the pair conversion helper itself.
- Because the list loader and `mSiteList` BYML expose `mUnitX/mUnitZ` s32 fields, the source pair is consistent with the parser's two s32 values. However, `StructurePresetA00` is not proven to be the runtime list object supplied to this exact invocation; the unit-field name correspondence is therefore a schema-compatible join, not an independently loaded live instance.
- The arithmetic identifies coordinate values, not the structure's final root/pivot. A ten-unit-spaced site center does not establish the building footprint or model origin.

## Remaining boundaries

1. **World frame/origin:** No trace here determines whether the coordinates are island-global, stage-local, or transformed again after the component vcall. No island-origin or world-root offset was recovered on this chain.
2. **Height and orientation:** Y remains untouched at conversion. No terrain-height-to-Y assignment, yaw/rotation conversion, or slope accommodation is proven.
3. **Footprint and placement validator:** The special branch reaches field-grid record predicates, but the record semantics and return meanings are not named from local native proof. Full-building footprint iteration, collision/overlap rejection, water/cliff restrictions, and preview placement feedback remain **OPEN**.
4. **Vtable destination:** The `+0x128` coordinate method and `+0x158` scalar callback remain unresolved targets. The object at actor `+0x68` is runtime-provided in this method; the present index has no static object instance/vptr binding for the executed action.
5. **Preview/build and persistence:** No exact `PreviewStructure`/`StructureStartPreviewGuide` transition is joined to this call, and no model, animation, collider/PBC, save-instance serialization, flush/reload, or day-change completion is reached. Catalogued asset names remain catalog references only.
6. **Story-slot role:** The selector proves an available six-entry index is chosen and passed through the parser, but no specific index is proven to be player home, bridge, villager plot, or facility. The six `StructurePresetA00` values must not be mapped to story roles by shape alone.
