# UI/HUD hit-test native follow-up

Tanggal: 6 November 2026. Sumber: ACNH 1.0.0 ExeFS `main`, SHA-256 `f8d248109ff72999b4600ae3749f8c7397fb960f7ad3ab8dee3018ae9e14e900`.

## Temuan tambahan

Kontrol button memang mencari pane bernama `B_Hit`. Helper `0x14885b0` menyimpan lookup tersebut pada field kontrol `+0x70` sebagai fallback; jika `+0x68` juga kosong, ia menyalin pointer fallback itu ke `+0x68`. Fungsi `0x14888b0` membaca `+0x70`, lalu `+0x68`, dan mengirim pane terpilih ke `0x14c80d0`. Caller `0x148b2b0` memakai hasilnya sebagai syarat memilih kontrol. Dengan demikian `B_Hit` terhubung secara native ke pemeriksaan visibilitas/aktivasi pane dalam kontrol button, selain crosswalk statis BND1 dan CNT1 yang tercatat sebelumnya.

Trace instruksi tambahan mempersempit celah itu. Konstruktor `0x14821d0` menempatkan hit node inline pada `control+0x200`; ia memberi `0x1485ab0` dynamic name field dari controller data bersama literal `"Hit"`, lalu menyimpan nilai balik ke `control+0x220`, yaitu node `+0x20`. Node yang sama kemudian dipasang dengan `0x14b87b0`. Pada callsite terpisah, `0x14885b0` melakukan lookup `Hit` dengan sumber nama `[params+8]+0x18`, context `[params+0x10]`, descriptor base dan token yang sama, lalu menyimpan hasilnya pada `control+0x420+0x70`. Ini membuktikan kedua jalur memakai input key yang sama; return pointer tidak dibandingkan langsung. Asset catalog memiliki 18 pasangan same-layout `B_Hit` BND1 + `B_Hit:Hit` CNT1. Jadi jalur native `*:Hit → node+0x20 → hit-test` dan crosswalk B_Hit terbukti statis, sementara nilai prefix dan kesamaan pointer langsung pada instance nyata tetap terbuka. Detail instruksi ada di [hit_node_link_static.json](../output/ui_hud/runtime_followup/hit_node_link_static.json), dibuat ulang oleh [ui_hud_hit_node_link_static.py](../tools/ui_hud_hit_node_link_static.py).

## Geometri batas dan prioritas hit

`0x14b7820` memeriksa pane dan rantai parent melalui `0x14c80d0`, lalu menguji titik terhadap rectangle pertama pada node `+0x30..+0x3c`. Jika pointer node `+0x28` non-null, ia menormalisasi rectangle kedua (`+0x40..+0x4c`) dan menguji irisan kedua rectangle itu. Uji titik memakai batas inklusif. `0x14b84f0` memperbarui rectangle dengan mengambil Pane pointer di `+0x20` dan `+0x28`, kemudian menulis hasil transform ke rectangle pertama dan kedua. `0x14b87b0` memasukkan node anak ke daftar sibling dan, bila bit `0x40` pada flag node aktif, menyalin pointer `parent+0x28` ke `child+0x28`. Ini membuktikan bahwa rectangle kedua memakai konteks batas yang diwariskan dari parent; nama semantiknya tidak tertulis di kode dan belum dapat dipastikan sebagai clipping gambar.

Walker native `0x14b8850` menguji node biasa lebih dahulu, lalu menelusuri child melalui `+0x8` dan sibling melalui `+0x18`. Node yang lolos mengganti kandidat sebelumnya; pada urutan depth-first yang dikendalikan, hit terakhir menang. Cabang khusus dengan bit `0x200` aktif dan bit 0 mati menguji node dengan mode geometri lain dan langsung mengembalikannya jika cocok. Urutan ini membuktikan prioritas traversal untuk flag/link yang diberikan; ia tidak membuktikan urutan visual/Z dari layout nyata.

Runner [ui_hud_hit_geometry_native.py](../tools/ui_hud_hit_geometry_native.py) mengeksekusi instruksi asli untuk pemeriksaan visibilitas, irisan rectangle, dan walker. Ia membandingkan 18 kasus tanpa mismatch: enam kasus visibilitas, enam geometri batas, dua pewarisan pointer batas, dan empat urutan pemilihan hit. Pada dua kasus pewarisan, helper relasi-list `0x14d9aa0`/`0x14d9990` distub; bytecode native `0x14b87b0` yang menyalin pointer tetap dieksekusi. Pada empat kasus walker, hanya predikat geometri `0x14b7820` yang distub agar urutan kandidat dapat dikontrol. Hasil rinci ada di [native_geometry_priority.json](../output/ui_hud/runtime_followup/native_geometry_priority.json).

## Bagian yang masih terbuka

- Native memasukkan hasil lookup token `Hit` ke node `+0x20`; lookup `Hit` yang disimpan pada kontrol `+0x70` memakai sumber nama, context, descriptor base, dan token yang sama. Delapan belas record aset cocok dengan nama `B_Hit:Hit`. Nilai dynamic prefix instance hidup tidak tercatat, dan kode tidak membandingkan dua return pointer secara langsung.
- Pointer batas kedua diwariskan dari parent saat bit `0x40` aktif dan dipotongkan terhadap batas pertama. Kode tidak memberi nama field itu sebagai clip/scissor, sehingga peran render dan peran interaksi tetap perlu dibedakan lewat bukti lebih lanjut.
- Urutan hit terbukti sebagai urutan traversal child/sibling untuk fixture. `0x192fb20` menjalankan pane callback slot `+0xa8` sebelum traversal child slot `+0xa0`; namun hubungan urutan hit-test dengan urutan pane BFLYT, stacking visual/Z, dan pilihan target saat event UI/game nyata belum teramati.
- **[NATIVE + VTABLE]** Sambungan lengkap statis ditemukan untuk objek `ScissorPane`. Factory `0x14c89c0` memberi label `ScissorPane` dan membuat object `0x110` byte lewat constructor `0x14c8a90`. Vtable instance dari cell `0x330ee30` memiliki callback di slot `+0xa8`, target `0x14c8d30`; callback membaca enable byte `+0xe0` dan empat bounds `+0xf0..+0xfc`, mengambil context dari holder `0x330ed18`, lalu memanggil push `0x14c8fe0`. Jika enable byte mati, callback menghitung rectangle lewat transform matriks sebelum push. Generic renderer `0x192fb20` mengambil slot `+0xa8` dari vtable pane pada cabang flag yang memenuhi syarat lalu berjalan ke anak melalui slot `+0xa0`. Constructor juga mengaitkan auxiliary object pada `+0xd8` ke child list; vtable dari cell `0x330ee38` mengarahkan slot `+0xa8` auxiliary itu ke thunk `0x14c8e90` → restore helper `0x14c9250`.
- **[NATIVE FIXTURE]** Runner mengeksekusi setter, callback bounds secara langsung dan lewat dispatch `0x192fb20`, helper stack push dua tingkat, restore ke tingkat sebelumnya, restore stack kosong, serta thunk auxiliary. Sebelas pemeriksaan sintetis cocok tanpa mismatch. Batas push dan apply direkam stub; tidak ada BFLYT live instance atau NVN command yang dijalankan.
- `0x14c90e0` memilih pemanggilan gabungan `0x19a9960` atau pasangan `0x19a9c60` + `0x19a9d50`; resolver memasangkan cell `0x3317c60` dengan `nvnCommandBufferSetScissor` dan `0x3318808` dengan `nvnCommandBufferSetViewport`. Kedua API dipanggil dengan rectangle piksel yang dihitung oleh `0x19a9a80`/wrapper terkait. Helper menerapkan lima kasus mode koordinat (label enum belum diketahui), menskalakan terhadap ukuran logis viewport ke batas piksel target, lalu memotong origin dan ukuran ke integer.
- Runner [ui_hud_scissor_coordinates_native.py](../tools/ui_hud_scissor_coordinates_native.py) mengeksekusi helper asli `0x19a9a80` dalam Unicorn untuk mode 0–5. Keenam origin piksel hasilnya cocok dengan transform yang diturunkan (0 mismatch); label enum tetap tidak diketahui. Input dan hasil ada di [scissor_coordinate_native.json](../output/ui_hud/runtime_followup/scissor_coordinate_native.json).
- Pemetaan koordinat itu membuktikan transform native statis untuk jalur renderer umum. Bounds `ScissorPane` kini terbukti mencapai helper push dalam callback render native dan jalur generic renderer. Call order callback terbukti untuk flag fixture, tetapi clipping hasil draw pada layout riil serta urutan sibling/stacking belum. Konvensi origin framebuffer, flag aktif pada instance BFLYT nyata, kapan auxiliary restore berjalan pada traversal riil, dan cakupan pixel aktual belum ditentukan.
- Tidak ada capture game sinkron, sehingga kecocokan titik layar, transform, skala viewport, dan pixel belum tervalidasi.

Runner [ui_hud_scissorpane_restore_native.py](../tools/ui_hud_scissorpane_restore_native.py) mencocokkan relocated vtable entries, setter (2), callback render (2), stack push/restore (4), dan restore thunk (3): total 11 pemeriksaan tanpa mismatch. Stub hanya menggantikan batas `0x14c8fe0` pada trace callback serta `0x14c90e0` pada uji stack; hasilnya ada di [scissorpane_restore_native.json](../output/ui_hud/runtime_followup/scissorpane_restore_native.json).
