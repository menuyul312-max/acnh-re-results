# Follow-up runtime UI/HUD: BND1 dan hit-test sentuh

Audit ini menelusuri dua jalur native yang berdekatan: pane BND1 bernama `B_Hit` menuju hit-test sentuh, dan SCR1 `ScissorPane` menuju stack scissor renderer. Klaim di bawah dibedakan antara analisis statis dan fixture instruksi native sintetis; tidak ada capture game.

`[TBL]` Katalog aset berisi 158 record BND1 dan 2 record SCR1. Delapan belas record BND1 bernama `B_Hit`; masing-masing memiliki record CNT1 pada layout yang sama dengan binding `B_Hit:Hit`. Pemasangan tersebut mencakup 11 `ButtonNormal`, 4 `ButtonRepeat`, dan 3 `ButtonCheck`. Daftar pasangan layout, ukuran BND1, serta sumbernya ada di [bnd1_hit_test_trace.json](../output/ui_hud/runtime_followup/bnd1_hit_test_trace.json).

`[NATIVE DATAFLOW + TBL]` Konstruktor kontrol `0x14821d0` membentuk inline hit node di `control+0x200`. Ia membangun lookup menggunakan dynamic name field dari controller parameters dan literal token `Hit`; hasil `0x1485ab0` ditulis ke `control+0x220`, persis sama dengan `node+0x20`. Kemudian node itu dipasang ke parent lewat `0x14b87b0`. Lookup `Hit` kedua pada helper `0x14885b0` memakai sumber dynamic name `[params+8]+0x18`, context `[params+0x10]`, descriptor base, helper, dan token literal yang sama; hasilnya disimpan pada subobject `control+0x420+0x70`. Ini membuktikan kedua jalur meminta pane dengan key yang sama, tetapi kode tidak membandingkan dua nilai baliknya. Katalog aset mencatat 18 same-layout `B_Hit:Hit` binding, jadi jalur tersebut cocok kuat dengan BND1 bernama `B_Hit`; nilai prefix hidup dan pointer identity langsung belum tercatat. Instruksi dan batas bukti ada di [hit_node_link_static.json](../output/ui_hud/runtime_followup/hit_node_link_static.json), dibuat oleh [ui_hud_hit_node_link_static.py](../tools/ui_hud_hit_node_link_static.py).

`[PSEUDO]` Pada jalur sentuh, `0x14b94c0` memanggil traversal `0x14b8850` di `0x14b958c`, lalu menyimpan node hasil pada offset `+0x38` record pointer di `0x14b9594`. Traversal memeriksa node dan keturunannya melalui `0x14b7820`, memakai child link `+0x8` dan sibling link `+0x18`. Jalur lanjut yang sudah dipetakan mengirim target tersimpan melalui `0x14b8950`, lalu traversal kontrol `0x14b7a10` mencocokkan target itu.

`[PSEUDO]` Helper `0x14b7820` membaca dua persegi panjang float dari offset node `+0x30..+0x3c` dan `+0x40..+0x4c`. Jika field terkait persegi panjang kedua pada `+0x28` tidak null, instruksi AArch64 memilih batas yang beririsan sebelum membandingkan titik sampel dengan rectangle hasilnya. Ini membuktikan ada perpotongan geometri pada hit-test. Bukti yang ada tidak memberi nama semantik untuk rectangle kedua, sumber koordinat, atau aturan prioritas saat beberapa node cocok.

Batas penting jalur hit-test kini lebih sempit: node `+0x20` menerima hasil lookup dengan token `Hit` dan kemudian dipakai oleh hit-test; lookup `Hit` kontrol di `+0x70` dibangun dari sumber nama dan context yang sama. Delapan belas record aset mencocokkan nama `B_Hit:Hit`. Return kedua lookup tidak dibandingkan oleh native, sehingga pointer identity langsung belum terbukti. Pada child dengan bit `0x40`, helper attach menyalin parent `+0x28` ke child `+0x28`; hit-test memakai pointer itu untuk rectangle sekunder yang diiris dengan rectangle pertama. Kode tidak memberi label field ini sebagai clip. Pemilihan hit target node yang tumpang tindih dan pemetaan koordinat hit-test ke ruang layar masih belum diuji terhadap instance/capture game.

## Jalur render SCR1 ScissorPane

`[NATIVE STATIC]` Factory `0x14c89c0` memberi label objek `ScissorPane` dan mengalokasikan `0x110` byte melalui constructor `0x14c8a90`. Factory memasang vtable dari cell `0x330ee30`; address point yang direlokasi memiliki callback di slot `+0xa8`, target `0x14c8d30`. Setter `0x14c8d00` menandai enable byte `+0xe0` dan menyalin empat float ke `+0xf0..+0xfc`. Callback `0x14c8d30` membaca nilai tersebut, mengambil pointer scissor context lewat holder global `0x330ed18`, lalu memanggil push `0x14c8fe0` dengan bounds tersebut. Bila byte enable mati, callback menghitung bounds lewat transform matriks pane sebelum melakukan push.

`[NATIVE STATIC]` Generic pane renderer `0x192fb20` mengambil callback dari object vtable `+0xa8` pada cabang yang lolos flag pane, lalu menelusuri child list dan memanggil slot `+0xa0` pada anak. Constructor `0x14c8a90` juga membuat auxiliary object di offset parent `+0xd8`, memasang vtable kedua dari cell `0x330ee38`, dan mengaitkannya ke list child; slot `+0xa8` pada address point kedua adalah thunk `0x14c8e90`, yang meneruskan ke restore helper `0x14c9250`. Push/restore menyimpan hingga enam rectangle bertingkat dan mengiris input dengan rectangle teratas. Jika irisan terbalik, push menerapkan empat nilai nol; pada count enam push masih menerapkan irisan berikutnya tetapi tidak menyimpannya. Restore saat stack kosong juga mengirim rectangle nol. Helper `0x14c90e0` mengarahkan mode 1 ke update viewport/depth dan scissor terpisah, sementara mode 0 memakai update gabungan; GOT API resolver menghubungkan keduanya ke string NVN `SetViewport`/`SetScissor`. Rincian API dan transform pixel ada pada [scissor_static_path.json](../output/ui_hud/runtime_followup/scissor_static_path.json).

`[NATIVE FIXTURE]` Runner [ui_hud_scissorpane_restore_native.py](../tools/ui_hud_scissorpane_restore_native.py) menguji setter, callback render secara langsung dan melalui `0x192fb20`, push dua tingkat, restore ke tingkat sebelumnya dan stack kosong, serta restore thunk. Kesebelas pemeriksaan sintetis cocok tanpa mismatch. Push callback dan batas penerapan rectangle hanya direkam oleh stub; runner tidak mengeksekusi NVN, menginstansiasi archive BFLYT, atau mengukur pixel game. Hasilnya ada di [scissorpane_restore_native.json](../output/ui_hud/runtime_followup/scissorpane_restore_native.json).

Temuan tersebut menutup jalur statis `ScissorPane instance → generic renderer callback → stack context → NVN apply path`. Yang masih belum terbukti adalah callback/flag mana yang aktif untuk instance BFLYT nyata, kapan auxiliary restore berjalan pada semua kondisi traversal, cakupan pixel clipping, origin framebuffer, dan paritas render. Semua memerlukan capture game sinkron dengan layout, resolusi, viewport, dan orientasi yang diketahui.

## Pembaruan lifecycle, routing input, dan flag render

Laporan lanjutan [UI_HUD_LIFECYCLE_FOLLOWUP.md](UI_HUD_LIFECYCLE_FOLLOWUP.md) menambahkan batas statis untuk loader/lifecycle halaman, jalur Npad-ke-aksi, identitas pane `Hit`, serta flag callback renderer. Slot getter layout page terbukti sebagai crosswalk, tetapi handoff ke loader dan lifecycle scheduler masih belum ditemukan. Method sampling Npad tidak memiliki direct call ke dispatcher aksi umum; kemungkinan edge virtual atau state perantara belum tertutup.

Ada dua rincian flag yang perlu dipertahankan. Renderer umum `0x192fb20` menguji bit mentah pada objek pane sebelum memanggil callback `+0xa8`, tetapi disassembly tidak memberi nama semantik active flag. Byte `ScissorPane +0xe0` memilih bounds yang sudah disimpan dibanding bounds transform hasil pane; kedua cabang tetap mencapai stack push. BFLYT mengatalogkan semua 18 `B_Hit` dan dua ScissorPane sebagai `visible=true`, tetapi nilai live object tidak tersedia. Rincian instruksi ada di [page_input_renderer_static.json](../output/ui_hud/runtime_followup/page_input_renderer_static.json), dibuat oleh [ui_hud_lifecycle_static_trace.py](../tools/ui_hud_lifecycle_static_trace.py).

Tidak ada capture live sinkron yang menyandingkan page event, Npad sample, pointer pane, flag renderer, dan output GPU. Worktree ini juga hanya memiliki input ExeFS `main`; bukti RomFS tersedia sebagai output katalog sebelumnya, bukan arsip mentah untuk diurai ulang.
