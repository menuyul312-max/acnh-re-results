# UI/HUD lifecycle, input routing, and renderer flags

Status: 7 November 2026. Source build: ACNH 1.0.0 ExeFS `main`, SHA-256 `f8d248109ff72999b4600ae3749f8c7397fb960f7ad3ab8dee3018ae9e14e900`. This follow-up reads the available native image, the shared read-only index, committed RomFS-derived catalogue records, and the available relocated main.elf pointer map. It does not contain a synchronized game capture.

## Page loader and lifecycle

`[NATIVE STATIC + RELOCATION]` The catalogue still contains 135 page factories following the common constructor/registration pattern. Each observed page pointer sequence has slot 46 (`+0x170`) relocated to a unique three-instruction string getter; 134 return a name that matches a catalogued BFLYT and `SwkbdPage` returns `SwkbdDummy`. The page audit finds no direct `B`/`BL` instruction to any of the 135 getter targets. This proves a page-to-identifier crosswalk, not that a scheduler calls the getter or passes its result to the layout loader.

`[NATIVE STATIC]` All 135 factories call the shared registration helper `0x1da8220`. It calls `0x1da40b0`, which writes `2` at page object `+0x48` and branches through page slot 5 (`+0x28`) to `0x1da5380`; it then inserts an intrusive-list node and increments a collection count. The earlier helper `0x1da8210` writes `1` at the same offset. Those are observed values and transitions; the field is not identified as an open, active, or visible state.

`[NATIVE STATIC + INDEX]` A direct-call ordering check across every catalogue factory finds the same sequence in all 135: helper `0x1da8210` (store 1 at `+0x48`), common page initializer `0x1144600`, then registration `0x1da8220` (store 2 at `+0x48`, virtual slot 5 and collection insertion). No conditional or unconditional branch occurs between those callsites in any of the 135 factory functions. This proves a straight-line construction transition, but the numeric values remain unnamed.

`[NATIVE STATIC + RELOCATION]` A second path creates the native-string `RootPage`. Method `0x1dd4090` allocates `0x1c8` bytes, calls constructor `0x1da5b50` (whose indexed string reference is `RootPage`), stores the object at owner offset `+0x448`, then calls `0x1da40a0` and `0x1da40b0`. The constructor initializes page `+0x48` to 0; those helpers write 1 and 2. The state-2 helper dispatches through the new object's slot `+0x28`. The RootPage vptr is installed from relocation cell `0x3321ed0`, whose resolved address point is `0x31dcc00`; slot 5 points to `0x1da5c60`, which writes 3 to `+0x48`. The complete construction sequence is therefore `0→1→2→3`. Separately, UIMgr constructor `0x1dd3bd0` has native string references `UIMgr` and `UIMgr::PreCalc` and installs address point `0x31e0ba0` from cell `0x3322938`; this ties `0x1dd4090` at slot 10 to the UIMgr dispatch table. The method has no indexed direct caller and does not call collection inserter `0x1da8220`.

`[NATIVE STATIC]` The shared numeric field has further concrete transitions, still without semantic names. `0x1da7030` proceeds only from state 1, stores 2, and updates a pending-work mask; `0x1da7150` handles states 0, 2, and 5, checks child-resource conditions, and can return state 2 to 1. The related finish/close helpers show additional values: `0x1da4890` stores 4 and recursively invokes page callbacks; `0x1da4210` moves states 4/6→5, 3→2 after list removal, 5→7, and 2→8 before calling `0x1da43d0`; that finisher turns 4/6→3, 5→2 after unlinking, and 7→8 after unlinking and a virtual call. These are raw state transitions, not evidence that the integers mean open, active, closing, or visible.

`[NATIVE STATIC + POINTER INVENTORY]` The UIMgr sequence `0x31e0ba0` contains `0x1dd4390` at slot 12 and `0x1dd43a0` at slot 13; they tail-branch to `0x1da4890` and `0x1da43d0`. Slot 22 (`0x1dd43b0`) calls `0x1da4cd0` on the RootPage at `+0x448`, then calls `0x1da7030` and `0x1da7150` on a separate page object at `+0x420`. There are no indexed direct callers of slot-22 function `0x1dd43b0`; its body connects page-tree callbacks and numeric processing, but does not establish an outer scheduler or tick cadence.

`[NATIVE STATIC + RELOCATION]` UIMgr constructor `0x1dd3bd0` builds a callback descriptor with label `UIMgr::PreCalc` at `+0x378`, then stores the relocated target `0x1dd3e70` at `+0x390` and its owner at `+0x388` while holding the callback mutex. This is separate from the UIMgr vptr slot 10 method `0x1dd4090`, which constructs and stores RootPage. The named PreCalc callback increments UIMgr `+0x500`, runs `0x1da4960` on RootPage `+0x448`, and calls `0x1da4790(root, 1)`. When RootPage `+0x48` is 3, `0x1da4790` calls `0x1da4890`, which writes 4; the helper then performs mask-gated `+0x50/+0x54` work and recurses over child pages. This identifies the static callback that can produce `3→4`. Its subsequent tree work includes recursive helpers that call page vtable slots `+0x48`, `+0x50`, then conditionally `+0xa0` and `+0x58`; a separate helper called from UIMgr slot 22 walks RootPage children through slot `+0x70`. The PreCalc callback has no indexed direct caller, so its external dispatcher, runtime cadence, and order relative to draw events remain unknown.

`[NATIVE STATIC + INDEX + RELOCATION]` The draw-event constructor registers four members through `0x1a24ef0`: index 0 `drawParticlePreLayout`, index 1 `drawLayout`, index 2 `drawParticlePostLayout`, and index 3 `drawUser`. Each member has a distinct callback relocation: `drawLayout` → `0x1c805d0`, pre-layout → `0x1c806b0`, post-layout → `0x1c806c0`, and user → `0x1c806d0`. Only `drawLayout` reaches RootPage: its callback checks a global gate and input byte `+0x202`; values 1 and 2 build an event context and call `0x1dd4560`, while other values tail-call `0x1dd44c0` with a null second context. Both manager methods pass the context to `0x1da4db0` on RootPage `+0x448`. That helper returns at state 3; otherwise it recursively walks children and calls each page's virtual slot `+0x78`. The particle pre/post thunks pass event IDs 10/11 to `0x1c80850`; the user callback follows a separate path that calls slot `+0xb8` on a global user-draw manager. The mapping from draw-layout byte `+0x202` to an event label and all event scheduler ordering/cadence remain unknown.

The only indexed direct caller of candidate selector `0x1da8270` is `0x1cbac50`. That selector walks a collection, calls page slot 17 (`+0x88`), whose common thunk forwards to slot 30 (`+0xf0`), and returns an entry address when the result bit is set. This is a selection predicate for a candidate collection entry; the available code does not connect it to slot 46, a page scheduler, or a global open/close/back stack. Loader handoff, page update scheduling, modal order, focus restoration, and page teardown remain unresolved.

## Hit-pane identity and declared visibility

The controller constructor and the separate controller-side `Hit` binding use the same dynamic name source, lookup context, descriptor base, helper, and literal token `Hit`. The first lookup result is stored at inline hit node `+0x20`; the second is stored at controller `+0x420+0x70`. Native code does not compare those returns. The asset catalogue gives 18 same-layout `B_Hit` BND1 / `B_Hit:Hit` CNT1 pairs, and all 18 BND1 records declare `visible=true`. This strengthens the static name crosswalk, but the dynamic prefix and an instance pointer comparison are absent.

The BFLYT catalogue also contains two `ScissorPane` records, `S_Scissor_00` and `S_Scissor_01` in `LMyDesignEditCanvas`; both declare `visible=true` and size 650×650. These are serialized asset properties, not current runtime flag values.

## Renderer gates and ScissorPane bounds flag

`[NATIVE STATIC + RELOCATION]` The separately string-referenced ScissorPane factory `0x14c89c0` allocates through two branches, and both call base Pane constructor `0x192d3d0` (`0x14c89f0` and `0x14c8a34`). That base constructor initializes byte `+0x58` to `0x11` and zeros the halfword beginning at `+0x5b`; these defaults fail the generic renderer gate below. The factory installs address point `0x313a398` from relocation cell `0x330ee30`, with generic renderer `0x192fb20` in slot 20 and ScissorPane callback `0x14c8d30` in slot 21. The non-null-input branch ORs bit 3 into pane `+0x58`; the null-input branch does not. That bit-3 write alone does not satisfy the generic renderer's `0x81` mask gate. At `0x14c8a78`, the factory calls `0x14c8a90` to construct a separate auxiliary object at parent `+0xd8`; that object's relocated dispatch sequence is used for the restore child callback.

`[NATIVE STATIC + INDEX + RELOCATION]` BFLYT type dispatcher `0x19212e0` recognizes the four-byte `scr1` tag, allocates `0xe0` bytes, and calls `0x1937280`. That constructor calls wrapper `0x192d450`, which initializes the pane child links and tail-branches to `0x192d490`. The wrapper has eight indexed direct callers; this chain proves that the SCR1 layout record reaches the Pane parser despite the parser's zero direct-call count. The parser initializes `+0x58/+0x5c`, reads source bytes `+8/+0xb` into those fields, conditionally edits bits 1 and 2, and later ORs bit 4 into `+0x58`.

`[NATIVE STATIC + RELOCATION + API RESOLUTION]` The SCR1 constructor installs address point `0x31a2ff8` from relocation cell `0x3318e10` (`0x31a2fe8 + 0x10`). Its slot 19 (`+0x98`) is `0x192edc0`, slot 20 (`+0xa0`) is `0x19372b0`, and slot 21 (`+0xa8`) is return-only thunk `0x192fc90`. The generic Pane child traversal calls child slot `+0xa0`, providing the edge from the parsed child node to this renderer. `0x19372b0` checks pane `+0x58` bit 0 and `+0x5a` nonzero before computing a clipped rectangle, dispatches it through `0x18faf70`, calls generic renderer `0x192fb20`, then dispatches saved context to restore. The previously indirect target in `0x18faf70` resolves to NVN `nvnCommandBufferSetScissors`: resolver `0x18fb3f0` resolves the exact API string and stores it in cell `0x3317bf8`, which the wrapper calls at `0x18fafd8`. The wrapper takes its command-buffer/context pointer from incoming `+0xb8`, packs source records of stride `0x20` into 16-byte rectangle entries, and forwards the incoming first index and count. SCR1 calls the wrapper at `0x1937494` and `0x19374c8` around generic Pane rendering. If either SCR1 gate fails, the renderer uses generic drawing without this clip wrapper. The separate `0x14c89c0` factory path invokes `0x14c8d30` through its slot 21; the static evidence does not show that every SCR1 pane is created through that factory.

`[NATIVE STATIC + RTTI + POINTER INVENTORY]` The table at address point `0x31a2690` has RTTI name `nn::ui2d::LayoutPaneFactory`; its slot 2 is `0x19212e0`, slot 4 is `0x1921ed0`, and slot 5 is `0x19215b0`. Method `0x1921ed0` contains an indirect call through slot `+0x10` on argument `x22` at `0x1921f20`, then traverses the same argument as a `+0x20/+0x28` list. The available native flow does not establish that `x22` is a `LayoutPaneFactory` or that this call resolves to `0x19212e0`. There is no indexed direct caller of `0x19212e0`, and the executable main image has no ADRP+ADD/LDR reference to the `LayoutPaneFactory` cell/address point; that bounded scan does find the known SCR1 constructor cell. Thus the static type arm and constructor are proven, while the outer loader invocation and active resource object are not. The catalogue identifies the two serialized SCR1 instances as `S_Scissor_00` and `S_Scissor_01` in `LMyDesignEditCanvas.Nin_NX_NVN.zs!blyt/LMyDesignEditCanvas.bflyt`, each visible, translated `(0,-10,0)`, and sized `650×650`.

`[NATIVE STATIC + WRITER SCAN]` A fixed-displacement store scan over indexed functions in `0x192d000..0x1930000` finds six generic Pane functions and 19 writes starting at non-stack base offsets `+0x58/+0x5c`: base constructor `0x192d3d0`, layout parser `0x192d490`, clone/copy `0x192e290`, runtime state update `0x192edc0`, attribute update `0x192f4c0`, and child flag propagation `0x192fe30`. The adjacent-store check finds one additional overlap: base constructor `0x192d3d0` zeros a halfword at `+0x5b..+0x5c`. The clone copies both flag bytes, clears `+0x58` bit 5, and sets bit 4; `0x192f4c0` sets `+0x5c` bit 6; `0x192fe30` can clear `+0x58` bit 4 recursively. The state update `0x192edc0` appears in slot 19 of both the `0x14c89c0` ScissorPane address point and BFLYT SCR1 address point. On its ordinary path it updates alpha `+0x5a`, recursively calls child slot `+0x98`, then sets `+0x58` bit 7 and `+0x5c` bit 4; one early path clears bit 7 and returns. That ordinary path supplies two generic renderer gate bits, while source/layout/runtime state supplies the remaining conditions. The method has indexed callers, but no recovered edge establishes when slot 19 runs on a live ScissorPane/SCR1 instance. This exhausts fixed-displacement starts and overlapping wide writes in the selected Pane family, not register-computed writes or every possible object write in the image; a whole-image exact-offset scan includes unrelated structures. `VisibleOn`/`VisibleOff` references occur in page functions `0x1258d10` and `0x12ece60`, both of which call `0x1683190`; no recovered write connects those labels to renderer bytes.

`[NATIVE STATIC + INDEX + POINTER INVENTORY]` A separate UI-range producer in the Swkbd page, `0x14c81b0` (only indexed caller `0x1508390`), finds three `N_Padding` child nodes and ORs bit 4 into their `+0x58` bytes while updating position data. It neither writes `+0x5c` nor sets the generic renderer gate's required `+0x58` bits 0 and 7. Shared helper `0x14c8490` also ORs bit 4 into destination `+0x58`; it has five direct callsites from methods occupying slot 7 in relocated UI pointer sequences, but those sequence owners are unnamed. Neither path is connected to the BFLYT SCR1 type case or the `0x14c89c0` ScissorPane factory. A bounded `0x14c8000..0x14ca000` store scan also finds offset matches in static configuration and Gradation payload routines, which cannot be counted as base Pane flags from displacement alone. A whole-image exact-displacement scan yields thousands of same-offset stores across unrelated native structures, so exhaustive class attribution stops at typed Pane methods and explicit ScissorPane factory branches.

The generic pane renderer `0x192fb20` calls a pane vtable callback at `+0xa8` only when its raw object checks pass: byte `+0x58` has mask `0x81` set, byte `+0x5c` has bit 4 set, byte `+0x5a` is nonzero, and byte `+0x62` has bit 1 clear. It later traverses child panes through slot `+0xa0`. The SCR1 renderer has its own `+0x58` bit-0 and `+0x5a` tests before clip submission. These byte tests are not named as active-state flags by native code. The hit visibility helper `0x14c80d0` also checks bit 0 of pane byte `+0x58` and can walk ancestor panes according to its input options.

The ScissorPane setter `0x14c8d00` stores `1` in byte `+0xe0` and copies four 32-bit bounds to `+0xf0..+0xfc`. Its render callback `0x14c8d30` uses those stored values when `+0xe0` is nonzero; when it is zero, it derives a rectangle from the pane transform. Both branches reach the scissor-stack push call at `0x14c8e44`. Thus `+0xe0` selects the source of bounds; it does not disable the clipping callback. Native stack bookkeeping was exercised by the existing 11-case synthetic fixture, which stubs the push/apply boundaries and does not issue NVN commands.

The SCR1 layout-to-render chain is statically established through its type-switch case, constructor, tail-call parser wrapper, and slot-20 child renderer. The remaining static gaps are the outer resource-loader edge into `0x19212e0` and the indirect context callback reached by `0x18faf70`; the latter is not joined to the separately mapped NVN setter path. The independent `0x14c89c0` ScissorPane factory path is joined through the callback and scissor stack to NVN viewport/scissor setters, and its coordinate conversion maps logical bounds into target-pixel bounds using runtime viewport dimensions and pixel bounds. Live flags, transforms, viewport/framebuffer origin, target rectangle, and actual pixel coverage still require a synchronized capture.

`[NATIVE STATIC + API RESOLUTION]` The push helper `0x14c8fe0` intersects incoming left/top/right/bottom bounds with the current top entry. If the intersection is inverted on either axis, it replaces all four values with zero, then applies the result in mode 1 and stores it when the prior stack count is at most five (six saved rectangles). At count six, another push still applies its intersection but exits without saving or incrementing the stack. The restore helper `0x14c9250` decrements the count and reapplies the previous entry in mode 1; on an empty stack it applies a zero rectangle in mode 0. In `0x14c90e0`, mode 1 reaches separate viewport/depth (`0x19a9c60`) and scissor (`0x19a9d50`) updates, while mode 0 reaches the combined update (`0x19a9960`). The two paths resolve through the GOT cells associated with the `nvnCommandBufferSetViewport` and `nvnCommandBufferSetScissor` strings. This traces submission of transformed rectangles into native NVN calls; it does not prove the GPU's pixel coverage. In particular, the empty-stack logical zero rectangle still passes through the live viewport/coordinate transform, whose runtime values and displayed result were not captured. The existing fixture does not exercise balanced traversal beyond six saved entries.

The separate parent-bound pointer at hit node `+0x28` is inherited under node flag `0x40` and participates in hit-rectangle intersection. Native does not call that field a render clip. The SCR1 render wrapper proves flag-gated rectangle dispatch around generic Pane rendering, while the separate ScissorPane factory callback proves a distinct native NVN submission route. Which route and live bounds apply to a given BFLYT instance, the resulting pixel coverage, and framebuffer origin remain unmeasured.

## Evidence boundary

The current worktree has the ExeFS `main` input and committed RomFS-derived catalogue JSON, but no raw RomFS archive under `inputs/`. RootPage construction and its `UIMgr::PreCalc` state `3→4` callback are mapped, as are named draw-event registrations and propagation into the child tree. The callback's outer cadence/order, remaining numeric state names, loader handoff, and live page instances are unresolved. The BFLYT SCR1 type case, layout flag conversion, and custom clip wrapper are mapped, but the outer resource-loader call and indirect context handler are not. No synchronized live capture aligns page events, Npad samples, controller parameters, pane flags/transforms, viewport origin, and GPU output. The independent NVN ScissorPane path maps logical bounds to runtime target-pixel bounds, but no target rectangle or pixel coverage was captured.
