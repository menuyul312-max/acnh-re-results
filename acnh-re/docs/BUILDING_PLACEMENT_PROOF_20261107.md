## Evidence and provenance rules

Evidence labels describe what a source can establish:

- **EF** — EventFlow graph/source reference. It proves that the named event, actor, parameter, flag, query, or stage request is present in the graph; it does not prove runtime handler behavior.
- **TBL** — BCSV table row and field evidence. Numeric IDs are scoped to the named table.
- **STRUCT** — parsed BYML/stage structure. A field or actor record does not establish its semantic role or runtime consumer by itself.
- **PSEUDO** — static disassembly/pseudocode summary, not native execution.
- **NATIVE** — bounded execution under a recorded fixture. This workstream did not execute a building placement or lifecycle.
- **CAT** — model/audio catalog candidate only. A name match does not prove raw asset availability, resource selection, rendered mesh, audio playback, or collision geometry.
- **OPEN** — unresolved source, consumer, transform, mesh, or collider join.

Raw source paths, manifest IDs, sizes, and SHA-256 values are recorded in the JSON `source_inventory`. Raw BCSV/BYML/EventFlow provenance is from `acnh-re/output/manifest.json` (SHA-256 `eb8d114129e01e6c3284a7a2613c3f451d649c0708a58a1a08cd757c5f3840a8`). Resolved views were read from the existing analysis workspace and cross-checked against that manifest. The read-only index was `/workspace/acnh-re/output/index.sqlite` (SHA-256 `a78c7af27d37b8fd931bba8bc611623dacf7685cb6e8b4f827effa0765340aad`); the zero-byte checkout copy at `acnh-re/output/index.sqlite` was not used.

Relevant conversion/source tools are `acnh-re/tools/reference/acnh_rip/formats/bfevfl.py` and `acnh-re/tools/reference/acnh_rip/exporters/eventflow.py` (EventFlow structure), `acnh-re/tools/gameplay_flow.py` (flow tree/index), `acnh-re/tools/reference/acnh_rip/formats/bcsv.py` (BCSV), `acnh-re/tools/reference/acnh_rip/formats/byml.py` and `acnh-re/tools/typed_byml.py` (BYML), `acnh-re/tools/reference/acnh_rip/exporters/data.py` (data export), and `acnh-re/tools/byml_names.py` (recovered BYML key annotations). In BYML, `@` names are recovered hash-key annotations; raw hashes and types remain the authority. Numeric values from `ItemParam.UniqueID`, structure table `UniqueID` columns, EventFlow internal kind selectors, `SettlerType`, flags, and grid cells are distinct namespaces. No numeric cross-namespace mapping is inferred.

## World, site-cell, and collision boundary

The existing loader analysis in `acnh-re/docs/ISLAND_LOADER_FOLLOWUP.md` statically describes a generator/setup/resource chain through `0x529910 -> 0x552bb0 -> 0x528bf0 -> 0x558f40`; the whole generator and resource loading were not executed. `FieldMainFieldParam.bcsv` has 96 rows, `FieldOutsideTemplate.bcsv` 36, and `FieldLandMakingUnitModelParam.bcsv` 246. `FieldPresetA00_LandMaking.byml` is a 112×96 land-making grid; the examined write path moves 14-byte land-making cell data. A separate ground/collision record has stride 52 bytes, and no expansion/join from the land-making cell into that collision record is proved here.

`B_data/Param/Field/MainFieldPreset/StructurePresetA00.byml`, key `root.@StructurePresetA00.@mSiteList[]`, contains six `@mUnitX.s32`/`@mUnitZ.s32` cell pairs: `(61,66)`, `(78,77)`, `(49,79)`, `(88,80)`, `(97,84)`, `(69,90)`. These are **STRUCT** cell indices in one source preset. Their slot purpose and mapping to a player home, villager homes, facility, bridge or plot are **OPEN**. The native parser partially maps the selected adjusted pair into X/Z as `10*n+5`, and downstream field lookups quantize to five-unit cells; global origin/frame, height, rotation, footprint origin, final model transform, and collider remain **OPEN**. See [the coordinate conversion follow-up](BUILDING_SITE_WORLD_POSITION_TRANSFORM_FOLLOWUP_20261107.md).

The native follow-up [BuildingSiteIndex trace](BUILDING_SITE_INDEX_BLACKBOARD_NATIVE_FOLLOWUP_20261107.md) resolves a static consumer: the registered `BuildStructure` candidate selects an available index from a six-entry list, writes it to the actor AI blackboard as `BuildingSiteIndex`, and passes the parsed selected pair into actor-context code. The [coordinate conversion follow-up](BUILDING_SITE_WORLD_POSITION_TRANSFORM_FOLLOWUP_20261107.md) proves the adjusted pair becomes X/Z `10*n+5` and enters a dynamic component call, but not that the runtime list instance is `StructurePresetA00`, which story structure owns each index, or the final world transform.

The player movement collider query at `0x7bccf0` is documented in `acnh-re/docs/PLAYER_COLLIDER_QUERY_REMAINDER_20261107.md`; the sandbox probe stops at an uninitialized world root. That query does not identify placement validation, building footprint geometry or a structure PBC consumer. All building-placement collision joins remain **OPEN**.
